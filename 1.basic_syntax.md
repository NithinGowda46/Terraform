# Lesson 01: Terraform blocks, arguments, and parameters

This lesson introduces a few basic Terraform words and uses them to create a small text file on your computer.

## The basic words

### Block

A **block** is a named section of Terraform configuration. It has a block type, labels, and a body in braces.

For example, `resource` is a block type here, `local_file` and `my_file` are its labels, and the lines inside `{ }` are its body:

```hcl
resource "local_file" "my_file" {
  filename = var.filename
  content  = var.content
}
```

Other block types in this lesson are `terraform`, `variable`, and `output`.

### Argument

An **argument** assigns a value to a named setting inside a block. For example, `filename = var.filename` assigns a value to the `filename` argument of the resource.

Arguments are written as `name = value`. The `filename` and `content` arguments tell the `local_file` provider what file to create and what text to put in it.

### Parameter

“Parameter” is a general programming word for an input. In Terraform, you will usually hear **input variable** for a value supplied to a configuration. This lesson declares `filename` and `content` as variables in `variables.tf`, then references them as `var.filename` and `var.content`.

## The blocks in this lesson

### `variable` block

A variable block declares an input and its type. A `default` makes that input optional when you run Terraform.

```hcl
variable "filename" {
  description = "Name of the local file Terraform will create."
  type        = string
  default     = "automate.txt"
}
```

The label `filename` names the variable. `description`, `type`, and `default` are arguments of the variable block.

### `resource` block

A resource block describes an object Terraform should manage:

```hcl
resource "local_file" "my_file" {
  filename = var.filename
  content  = var.content
}
```

The first label, `local_file`, is the **resource type**. It comes from the `hashicorp/local` provider and means a file on the local computer. The second label, `my_file`, is the name you choose for this resource in the configuration. Together, Terraform refers to it as `local_file.my_file`.

The values on the right use the two input variables. Their defaults create a file called `automate.txt` containing `best content` in this lesson's directory.

### `output` block

An output block shows a useful value after Terraform has applied the configuration:

```hcl
output "created_file_path" {
  value = local_file.my_file.filename
}
```

The output label is `created_file_path`. Its `value` argument reads the filename from the resource.

## Provider setup

The `terraform` block in `main.tf` declares the `hashicorp/local` provider. A **provider** is a plugin Terraform uses to manage a kind of service or resource. `terraform init` downloads the provider so Terraform knows how to create a local file.

## Commands to learn

Run these from the `lessons/01-basics` directory:

```sh
terraform init
terraform validate
terraform plan
terraform apply
```

1. `terraform init` prepares the folder and downloads the required provider.
2. `terraform validate` checks the configuration for errors.
3. `terraform plan` previews what Terraform intends to change. Look for the proposed `local_file.my_file` creation.
4. `terraform apply` performs the change. Review the plan and type `yes` when prompted.

After applying, inspect `automate.txt` in this directory. Terraform also records state in `terraform.tfstate`; state helps it track the resource. Treat state files as private because they may contain sensitive values.

To see the outputs, run:

```sh
terraform output
```

To remove the file through Terraform, run `terraform destroy` and confirm the plan. This removes the generated `automate.txt` file.

## Try changing the inputs

Preview different values without changing the defaults:

```sh
terraform plan -var="filename=practice.txt" -var="content=I am learning Terraform"
```

To apply those values, use the same options with `terraform apply`.
