# Terraform Block Types

Terraform configuration is made from blocks. A block starts with a block type, may have one or more labels, and contains arguments or nested blocks inside braces.

```hcl
resource "aws_s3_bucket" "app_data" {
  bucket = "my-app-data-bucket"
}
```

Here, `resource` is the block type, `aws_s3_bucket` and `app_data` are labels, and `bucket` is an argument. The resource type and arguments available depend on the provider.

## Common block types

These are the block types most Terraform users encounter in a module:

| Block type | Purpose |
| --- | --- |
| `terraform` | Sets Terraform-wide settings, such as the Terraform version requirement, provider requirements, and backend. |
| `provider` | Configures a provider, such as the AWS region Terraform should use. |
| `resource` | Declares infrastructure Terraform should create or manage. |
| `data` | Reads information about an existing object or other provider data without creating that object. |
| `variable` | Declares an input that can be supplied or customized when using the module. |
| `locals` | Defines reusable values calculated from expressions in the module. |
| `output` | Exposes a value from the module, such as a resource ID. |
| `module` | Calls another Terraform module so its resources and outputs can be reused. |

This is a list of common block types, not every specialized block in the Terraform language. Some blocks are nested inside other blocks. For example, `required_providers` is a nested block inside `terraform`, and `lifecycle` can be nested inside a `resource`.

## Example: create an S3 bucket

This example uses a `resource` block to ask the AWS provider to create an S3 bucket:

```hcl
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }
  }
}

provider "aws" {
  region = "ap-south-1"
}

resource "aws_s3_bucket" "app_data" {
  bucket = "my-unique-app-data-bucket"
}

output "bucket_name" {
  value = aws_s3_bucket.app_data.bucket
}
```

In this example, `terraform` declares the AWS provider dependency, `provider` configures AWS, `resource` declares the bucket, and `output` displays its name after Terraform applies the configuration. The bucket name must be globally unique in AWS. Creating it requires valid AWS credentials and can incur charges.

To create the bucket, run `terraform init`, review `terraform plan`, and then run `terraform apply` from the directory containing the configuration.
